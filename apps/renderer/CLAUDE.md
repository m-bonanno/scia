# Scia — Renderer CLAUDE.md (`apps/renderer`)

Loaded when working under `apps/renderer/`. **Extends** the root `CLAUDE.md`; wins for frontend work.

## Who uses this screen

Anyone who downloads files: they paste a link and want to forget about it. The window is often small and in a corner. **Minimal is the product**: one screen, one field, one list. A feature that needs a second screen has to earn it.

## Design canon

| Source                                 | What we take                                                      |
| -------------------------------------- | ----------------------------------------------------------------- |
| **Don't Make Me Think** (Krug)         | Self-evident controls; no manual                                  |
| **The Design of Everyday Things**      | Feedback for every action, constraints over error messages        |
| **[Laws of UX](https://lawsofux.com)** | Fitts, Hick (few choices), Doherty (< 400 ms to visible feedback) |
| **WCAG 2.2 AA**                        | Contrast, visible focus, labels, status messages                  |

### Hard visual rules

- **Tokens, never raw colours.** Colours come from the CSS variables of `src/themes.css`, named for Tailwind in `src/styles.css` (`bg-surface`, `text-muted-foreground`, …). No hex in components, no `dark:` variant, no class that names a theme: a colour that changes is a token, defined by every theme in its dark and in its light variant.
- **A theme is a whole set of tokens, twice** ([`docs/design/themes.md`](../../docs/design/themes.md)). A person chooses the theme in Settings (`Theme` in `@scia/contracts/theme`; the engine keeps it); the system chooses the variant. The page wears the theme named on `<html>` — the engine writes it into the page it serves, `lib/theme.ts` changes it — and the default one when none is named. A spec (`apps/desktop/src/theme-colours.test.ts`) holds every theme and variant to the same tokens, every pair of text and ground the page uses to WCAG 2.2 AA (4.5:1 for text, 3:1 for a bar, an icon, the focus outline), `--background`, `--foreground` and `--muted-foreground` to `WINDOW_COLOURS`, which main paints the window with, and the extension's stylesheet to the default theme. A new token, or a new pairing of two tokens in a component, is added to that spec's list of pairs — and a pairing is counted in every state: the focus outline on each ground a focusable thing can sit on, and selected text, which is `accent-foreground` on `accent` (`::selection` in `styles.css`), never a tint under the text's own colour.
- **One accent**, for progress and the primary action. Failure is `destructive`; a paused bar is not coloured: it wears `paused`, a tone of its own, darker than the accent and 3:1 on its track, but in Black Tie light, Earth dark and Wood Floor dark, where it is the secondary text's tone, lighter than the accent (the owner, #58; [`docs/design/themes.md`](../../docs/design/themes.md)). A ready or a queued bar is `muted-foreground`.
- **Two levels told apart by tone**: the background and the surface on it. No shadows, no decorative borders. A line survives only where it carries meaning: the focus outline, a field's boundary.
- **A field is known at rest by something at the contrast of text, never by its line** (the owner, #66): its boundary, `border`, is held to no ratio, and WCAG 1.4.11 asks 3:1 of what identifies a control. The add bar's field has its icon and its placeholder; a field with nothing else has a placeholder that says what goes in it (the key's: "Paste your API key"), in `placeholder:text-muted-foreground` — a pair the contrast spec holds at 4.5:1 on every ground a field sits on ([`docs/design/themes.md`](../../docs/design/themes.md)).
- **The segment bar is the signature**: each connection fills its own stretch of the file where that stretch is. Do not replace it with a plain bar.
- **Numbers are `tabular-nums`** and go through `lib/format.ts` (the one `LOCALE` of `@scia/contracts/locale`, a non-breaking space before the unit). Never `toFixed`, never string concatenation of amounts.
- **Icons: `lucide-react` only.** No emoji, and no arrow the system draws: a menu wears lucide's chevron (`features/settings/setting-select.tsx`). Icon-only buttons are `IconButton`, which requires a label — or `ConfirmButton`, which is one until it asks (both wear `components/button-styles.ts`).
- **Scrollbars are the page's own** (`styles.css`; the owner, #154): 8 px, always there where an area scrolls, no arrow buttons, the thumb `muted-foreground` and `foreground` under the pointer, on the area's own ground. Chromium's `::-webkit-scrollbar`, never `scrollbar-width` or `scrollbar-color`: Chromium lets those win and keeps the system's arrows with them.
- **Visible focus always**: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-ring`. Never a box-shadow ring, never `outline-none` without a replacement.
- **Motion says something or is not there**: a row arriving, a bar filling. `prefers-reduced-motion` turns it off.

## Behaviour

- **What went wrong is a notice at the bottom of the window** (`features/notices/`; the owner, #132): announced once, with a "Dismiss" ×, gone by itself after `NOTICE_MS` — but never while the pointer is on the notices or the focus is in them, and its whole time again after. Several stack, newest last, at most `NOTICES_AT_MOST`; the same text is shown once and its time starts again. What stays true — the engine not answering — is a notice with no × and no time, drawn last, below newer ones, counted among them, and gone when it is no longer true; a notice of the same text, or one that no longer fits beside it, is let go. Every way a notice leaves — dismissed, gone by itself, pushed out — hands the focus it held to the notice now in its place, else to the one before, else to the field (in Settings, the top of the dialog); but a × pressed with the pointer (`event.detail > 0`) hands it to nothing, so that the notices left are not held by it and go in their own time (the owner, #143). A press of the keyboard on a × hands it on. While Settings is open the notices are drawn inside its dialog: a modal dialog puts the rest of the page out of reach. While notices are shown, the areas that scroll beneath them — the list, the panel of the account — keep room under their end as tall as the stack (`room-under-notices` in `styles.css`, the height told by the stack; the owner, #143), and Settings keeps room only where the stack would lie over it (`roomOverDialog`): a dialog the notices do not reach does not move under the pointer that just pressed in it (the designer, #244). A control that takes the focus is scrolled clear of them, whether Tab moved it or the page did: Chromium keeps the first out of the scroll padding by itself, and the page's root scrolls every focus `nearest` while notices are shown — but the one a press of the pointer gives, a mouse's, a pen's or a finger's tap: moved under the pointer between press and release, the control would lose the click (marked at `mousedown`, which comes in the focus's own task; #244). Nothing that takes the focus is hidden under a notice (WCAG 2.2, 2.4.11). A message that belongs to a control stays by that control and describes it: what the engine refused of the text sent from the field (`aria-invalid`, `aria-describedby`, until the text is edited), the folder refused, the key not taken. A change in Settings the engine did not keep is a notice that names the setting (`settingNotChangedMessage`), and the control shows what the engine still keeps (#142).
- **The version is beside the name, and an update is offered there** (`features/update/`; the owner, #133; [ADR 0015](../../docs/adr/0015-a-restart-to-install-an-update.md)): the whole version, small; once main says an update is downloaded, a button "Update to <version>" that asks in a popover before restarting — or, while something runs or waits in the list, says the update installs at the quit and that pausing the downloads lets it restart now (the owner, #159), in words that stay true once the last download has ended, since the note stays until it is closed (#257). Main decides; the page asks main what is offered, at the start, when main says it changed and when it learns the settings, keeping only the last answer.
- **Every data view has its states**: connecting (nothing drawn, no flash), empty (says what is missing and what to do), engine unreachable (says so, keeps the last list), data.
- **Forgiving.** A finished download leaves the list at one press (the file stays), and so does a ready one, taken from the clipboard, which has nothing on the disk; it starts at its "Start", and "Start all" is beside the filters while any row is ready. Unfinished bytes are thrown away only after a second press in place, and a downloaded program is run only after a second press too (`components/confirm-button.tsx`). The button turns, in place, into the word of what it is about to do, and stays one element, so the focus stays on it. A press is one press however it is repeated: while the button asks, no later click of a burst is the answer, and neither are the repeats of Enter held down — of Enter alone, a held Tab walks on. When it has nothing to ask, a later click is refused only by the button that saw the one before it, so quick presses clear a list. A failed add never clears what was typed.
- **Keyboard-complete.** Paste anywhere adds the links; everything pressable is a `button`. A shortcut of the pointer (a double click on a finished row is one press of its "Open": it opens a file, and makes a program's button ask — it moves the focus there, and never answers the question) only repeats a button that is there.
- **A key is typed once and kept nowhere in the page** (`features/settings/integrations.tsx`). Its field hides it; the engine checks it and keeps it ([ADR 0004](../../docs/adr/0004-the-key-of-a-service.md)); the page forgets it when it is taken, at Cancel and when Settings closes, and no answer of the API carries it back. What the service or the system said of it is told by the field — which is marked invalid and described by it — each sentence true of every cause its code covers (`connectFailureMessage`), and never clears what was typed. While the key is being checked "Cancel" does nothing, and says so (`aria-disabled`): the check cannot be taken back, and a way back that is not one is not offered. A key kept and not read back at this start (`keyNotRead`) is said across the row under its head, below the ways to connect again, with "Disconnect" beside it for a person who will not connect again — drawn only while no way to connect is open or a code being asked for, and while it is on its way the ways to connect do nothing and say so (`aria-disabled`): in either order, its failure would otherwise be said by the key's field or the code, and its success leave the focus on nothing (#245) ([ADR 0023](../../docs/adr/0023-a-key-said-kept-once-it-can-be-read-back.md)).
- **A code to confirm on the service's site is the main way to connect a service, a key the other** (the owner, #136; [ADR 0013](../../docs/adr/0013-a-key-that-arrives-by-a-code.md)). "Connect with a code" shows the code, where it is confirmed as a person would type it (`alldebrid.com/pin`) and how long it works — said once, not ticking, a minute at least — and "Open AllDebrid", which asks main to open that page and is described by the code; with no main, in a plain browser, the place is enough, and Cancel takes the focus. A live region always in the row says the code and that Scia waits, or that a code is being asked for; "Get a new code" says "Getting a code…" and does nothing meanwhile, as "Connect with a code" does. Almost every press in the row moves the focus, so Enter pressed anywhere in it arms `swallowHeldEnter` (`components/held-enter.ts`, which the notices' × uses too): a held Enter asks for one code and presses nothing after it; and "Open AllDebrid" opens no page for the second click of a double click, also one whose first click asked for the code. The page reads what became of the code every two seconds while it waits, and stops when it connected or failed; a code that connected nothing says why and offers "Get a new code". Leaving the code — Cancel, "Use an API key" — tells the engine to forget it, also while it is still being asked for, and so does Settings closing on a code still being asked for: every ask carries its turn, and an answer to an ask that is no longer the last is not shown, and its code is forgotten too. **A code shown when Settings closes is left to the engine** (the owner, #146; ADR 0013, amendment): it waits for it as long as it works and connects it when it is confirmed. Settings opened again draws at once what it drew last — the last list of services, also while the engine does not answer, and the code a row left waiting while its time has not run out by the clock, with how long it has left — so that nothing appears late or moves; the row asks the engine at once what became of it, then at its pace, and says it: connected, or why not with "Get a new code". The page remembers only a code it left waiting itself; one being asked for, or failed, is forgotten at the close. A failure says the one that is news: a code that no longer connects takes back a sentence about a page not opened, and "no code given" replaces what the code before said. Nothing of the key reaches the page.
- **A magnet pasted or typed goes to the service** (the owner, #137; [ADR 0014](../../docs/adr/0014-magnets-through-a-service.md)): `pastedIn` finds links and magnets alike, and the field's button counts both ("Download 3 links" with a magnet among them). The field's placeholder names magnets ("Paste links or magnets") only while the page last learned that a service is connected, and says "Paste one or more links" otherwise (the owner, #150). A magnet is a row of its own above the downloads, in "All" and "In progress" (`MagnetRow`): its name, where the service is with it (`magnetLine`) on a bar of one stretch, Remove — Scia stops waiting, the service keeps it — and Retry once it failed, which hands the focus to Remove as it leaves; each is one press however it is repeated. Retry or Remove refused because the magnet moved on meanwhile is told in a magnet's words (`magnetActionMessage`). Links and magnets sent together are sent apart, and each in batches of `MAX_URLS_PER_REQUEST`, the most the engine takes in one request, as main sends a copy's (#142): what is refused is kept in the field, and the rest is taken. A magnet counts under "In progress". When its files are downloads it leaves the list, and they are there.
- **A link that opens into several files is a row of its own, above the magnets and the downloads, until its files are chosen** (the owner, #181; [ADR 0025](../../docs/adr/0025-a-link-that-opens-into-several-files.md); `BundleRow`): its folder's name, and a line (`bundleLine`) that says the service is asked — on a bar of one stretch — or how many files it lists and how much they weigh, how many more the service cannot get and how many were left out past the most it lists — a line that wraps, never cut: it alone says what the list leaves out — or why it gave none (`bundleFailureMessage`). Its files are boxes to tick (`components/check-box.tsx`: the system's checkbox, hidden, under a box in the page's tokens — the edge `muted-foreground`, ticked the accent and its mark; the label holds the hidden control, so a box reached by Tab is scrolled into sight, and the list keeps room on every side for its focus outline — CI's E2E measures both), every one ticked at first, under "All files", which says when only some are; "Download N files" starts the ones ticked, and with none is `aria-disabled` and says "Download". Once sent, the choice is held until the engine answers: Download and every box are `aria-disabled` and do nothing; a refusal gives them back, and a start that worked leaves them held until the row leaves — a second press never sends another choice, nor earns a notice that the link is gone (#53). Retry once it failed hands the focus to Remove; every press is one press however it is repeated. When the row leaves under a press of its own — "Download", Remove, and a copied folder's ready row under its Start, opened into one — a focus left on nothing goes to the filter in use (`pressedRows`, the ids those presses named); a row that leaves by itself — an album read, a link that opens into one file — moves no focus, and a focus that went elsewhere meanwhile stays there. A held "All files" pressed while only some are ticked keeps saying so (`indeterminate`). It counts under "In progress"; a refusal because it moved on is told in a link's words (`bundleActionMessage`).
- **The magnets of the account are in a panel beside the list** (the owner, #138; [ADR 0016](../../docs/adr/0016-the-magnets-of-the-account.md); `features/account/`). Its button in the title bar is there only while the page last learned that AllDebrid is connected — when the engine is reached, whenever Settings closes, and when the engine's events say the connected services changed (`connectedServices`: a code confirmed once Settings closed, #146) — and says whether the panel is open (`aria-expanded`); the panel is closed at first, and beside the list at every width, which narrows (the designer, #158: over it, a row would run into it in one tone). Opened, it takes the focus to its heading; Escape or its Close shuts it and gives the focus back to the button; a held Enter on either presses once (`swallowHeldEnter`). It asks when it opens and every `ACCOUNT_POLL_MS` after, one ask at a time — the ask of Settings closing waits for one on its way, and only the newer answer is drawn; never while the window is hidden, and shown again only once the last answer is a pace old; nothing once closed. Newest first. Its state is one sentence in a `role="status"` region always in the panel: connecting says nothing; an empty account says so and that a magnet pasted above is added to it; each refusal of the account says its cause and its remedy (`accountTrouble`: the sentences Settings says of it, but a refused key, which outside Settings says "In Settings, disconnect it and connect again"): one mended in Settings — the key refused, no service — stops the pace until Settings closes, which asks at once; one mended outside Scia keeps it, so that the next answer shows it mended; beside a list, every failure adds that the list is from before; a service not answering keeps the list from before and says so; an engine not answering says nothing here — its notice does. A ready magnet has Download, one element whatever it became: pressed, it is `aria-disabled` until a read begun after its request settled says what became of it; already in Scia's list, the same, and the line says "In Scia’s list"; refused, it says why (`accountMagnetMessage`) and is offered again. A row that leaves under the focus hands it to the heading; a focus that went elsewhere stays there.
- **When a control leaves the page under the focus, the focus goes to what takes its place**: from the key's field, or from the code, to "Disconnect" once connected; from the code to "Open AllDebrid" when it arrives (to Cancel with no main), and stays on that button as it becomes "Get a new code" when the code fails — React keeps the node; to "Use an API key" after the key's Cancel, to "Connect with a code" after the code's Cancel and after disconnecting. A focus left on nothing starts again from the top of the dialog. Only a focus that was on what left is handed on: one that went elsewhere meanwhile stays where it is. A notice dismissed with the pointer hands on nothing (above).
- **A capture in `docs/design/` shows the app as it is**: the PR that changes what one shows retakes it, from the real app (`docs/design/README.md`). Three exceptions, by the owner's word: the version #157 put in the title bar is not in the captures taken before it (#133); the update's note of #159 and #257 is not in `update-while-downloading*.png` (23 November 2026); and the logo #88 draws from the app icon's mark is not in the captures taken before it, but for those CI's E2E job takes (23 November 2026, on #156) — all three retaken in #156, in the owner's sitting on the release candidate.
- **The page never names a path.** It names a download by id; main asks the engine where the file is (`lib/bridge.ts`). It names no folder either: to change where downloads go it asks main, which shows the system's dialog and tells the engine, and then it reads the settings again — whatever main answered, and also when main failed. An answer from main is checked like any answer from outside (`isFolderChange`). Main fails for the system's dialog as for an engine silent before or after it, and the engine may take the folder after main stopped waiting: a failure, or an answer the page does not know, is a notice that the folder did not change (`FOLDER_NOT_CHANGED`) only when the folder read again is the one before — never the engine's "not responding", and never by the folder, which nobody blamed; a folder that changed says itself, and a read that fails is reported as any (#142).
- **What the engine keeps is learned from the last ask.** Settings reads at every opening, at every change, and after a folder was chosen; an answer is kept only when nothing was asked after it (`learn` in `features/settings/settings-dialog.tsx`), so a read asked before a change never undoes it on screen.

## Copy

- **English, sentence case.** Buttons start with a verb (_Download_, _Resume_); headings are nouns.
- **Errors: the fact, then the remedy where there is one.** _The file is no longer at this address._ No blame, no _Oops_. A sentence that names a cause is shown for that cause alone: the caller is told which it was, as data.
- API errors arrive as `error.code`; the text lives in `lib/messages.ts`. A download's failure is a `DownloadFailure` code, turned into text in `features/downloads/status-line.ts`.

## Code

- `features/<name>/` for a screen's parts, `lib/` for what several features share, `components/` for generic controls.
- The live list comes from `lib/live.ts` (server-sent events into `useSyncExternalStore`); commands go through `lib/api.ts`, which checks every answer with the contract's Zod schema.
- No `node:*`, no import of engine code (types are fine). The renderer is a web page.
- Component specs use Testing Library and query by role and name, as a person would find the control.
