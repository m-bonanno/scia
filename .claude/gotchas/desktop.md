# Gotchas — the desktop shell (Electron)

For a change to `apps/desktop/`, and for a harness that drives the real app (`docs/development/testing.md`, "Proving the real app"). Read with the general entries of [`.claude/gotchas.md`](../gotchas.md); each entry's story is in the issues it names.

- → A reading that marks a baseline — what was on the clipboard when it started — is tried refused, answered empty and answered late across an off and on; Electron 44 answers `''`, not a rejection, for a clipboard it cannot open (#131). The baseline belongs to its turn, and nothing is offered until a read of that turn has found it.
- → A harness that runs a run's local hosts in its own process never waits synchronously: a loop of `execFileSync` held the event loop, and the app sat at "Connecting…" (#100). Use `execFile`, awaited, or put the hosts in a process of their own.
- → A pixel read from the screen is the pixel of whatever is on top: `CopyFromScreen` read another window's purple (#52). `PrintWindow` with `PW_RENDERFULLCONTENT` reads the window as the system composes it.
- → A window another window covers stops drawing, and a capture then shows half of two variants (#52, #136). A harness that captures starts Electron with `--disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows --disable-renderer-backgrounding`, and waits for the transitions to end (`getAnimations()` empty) before every capture.
- → A harness closes Settings with its button, or waits for the dialog's `close` event before pressing again: a press in the same turn as a close is lost, and in a window that is not drawing the event never comes (#52, #67).
- → Two harnesses on one debugging port drive the same page, and the old one added every download a second time (#52). End the old one, and bound every `fetch` to the port with a timeout, before starting another.
- → A Start menu shortcut a harness makes for a development build carries Scia's app id, and the taskbar named the installed Scia "Electron" through it (#81, #85). Remove it when the run ends; a run that reads the taskbar first reads `Get-StartApps` for `app.scia.desktop`.
- → A script Electron runs ends on every road: an `app.whenReady().then(async …)` with no rejection handler, and a `spawnSync` with no `timeout`, kept `npm run icons` alive for ever (#86). Give it a handler that calls `app.exit(1)` with a message and a time limit on the spawn, and run it with a broken input and with the limit lowered.
- → A locked screen has no taskbar to capture: `CopyFromScreen` returns the lock screen (#81). Look for `LogonUI` before believing a capture, and read the shell's icons without the screen (`IShellItemImageFactory`, `Icon.ExtractIcon`, `WM_GETICON`).
- → playwright-core's `_electron.launch` tells the page the system asks for light, while main reads the real system, so a dark Windows got a light page under dark buttons (#155). Launch with `colorScheme: null`, set a variant in main (`nativeTheme.themeSource`), and record what main hands `setTitleBarOverlay`, which has no getter.
- → A system message Electron turns into an event is read in Electron's source at the version pinned: at `session-end` Electron 44 ends the process itself unless its own quit has begun (#262, #273). Begin the quit inside the handler and let it stand, wait for a program's end on its process, not its window, and give a fake the program's own order — the window gone first, the process later; a spec of what an end wrote reads the file, not the line a pipe relays.
- → A page's `window.close()` destroys the window at once, with no preventable `close`: a harness that wants what the X does follows `docs/development/testing.md`, "Proving the real app".
- → A harness's start that fails leaves its app running on its profile, and on Windows playwright-core's `app.process()` is the shell, not Electron (#104). Ask main for its pid at once after the launch, with a bound, end it with its tree (`taskkill /T /F`), wait for it to be gone, and fall back to the shell's tree.
- → A debugging port answers before the window has a page: a harness waits for a `page` target, not just for the port.
- → Node's `fetch` ends an answer whose body says nothing for 300 s, so main's stream from an idle engine was cut every five minutes, which no one-minute run showed (#51). A thing that lasts as long as the app is left alone for longer than every timer under it.
- → A holder made for something shown once does not fit something shown many times: one variable kept the last notification, and the others were collected with their click (#51). Hold every one that can still be clicked.
- → An end told from the one before only by a list in between is lost when the list does not come: a download that failed twice within a quarter of a second failed once, to main (#51, #55). Say the limit, or have the source say when it happened.
- → A conflict resolved in an adapter keeps both sides' lines and their order: the merge of the themes put main's ear behind an `await`, and a download that ended in it was taken for one ended before (#51).
- → `BrowserWindow.isVisible()` is false for a minimised window on Windows: "hidden in the tray" is not shown and not minimised (#45).
- → `BrowserWindow.isFocused()` is what the window believes, not what the system says (#51, #62). A harness that wants a window in front, or not, reads the system's foreground window, and does not assume its own request worked.
- → What Electron keeps for Scia is not on disk when its call returns: `safeStorage` on Windows writes its key to `Local State` seconds later, and a kill lost it (#69). Try what has to survive a kill with a kill (`taskkill /T /F`), soon after, and read on disk what it depends on before saying it is done ([ADR 0023](../../docs/adr/0023-a-key-said-kept-once-it-can-be-read-back.md)).
- → A very long profile path breaks Chromium's GPU cache (`The filename or extension is too long`): harmless in a scratch folder, a sign to shorten the path, not a bug of the app.
- → Over the DevTools protocol, Enter presses a focused button only when its `keyDown` carries `text: '\r'`: without it nothing is pressed, and the harness proves nothing while looking as if it had.
- → A real double click over the DevTools protocol is two `mousePressed`/`mouseReleased` pairs at one point, `clickCount` 1 then 2: `element.click()` from the page arrives with `detail` 0 and takes roads a pointer never takes.
