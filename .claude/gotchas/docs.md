# Gotchas — docs and runbooks

For a change to `docs/`, a `CLAUDE.md`, `.claude/` or `README.md`, and for a PR's body or title and an issue. Read with the general entries of [`.claude/gotchas.md`](../gotchas.md); each entry's story is in the issues it names.

- → `wc -m` counts bytes in a shell that sets no locale, as a session's does, and `—` or `→` is three of them (#319). Count characters with `LC_ALL=en_US.UTF-8 wc -m` or Python's `len`; Node's `length` counts UTF-16 units.
- → A PR that closes an issue cannot hand part of it to "later": #244 and #312 left steps to after the merge beside `Closes #N`, and the merge would have closed them untracked. Deliver it — a step of the owner's done and read back before the approving verdict — or put it in an open issue first and name that issue.
- → The numbers of a run are read from that run's record, and a body that tells of several runs says which run each belongs to (#53, #44). Count what a mutant failed from Vitest's JSON report (`--reporter=json`), never from a print a script cut short (#367).
- → An ADR and a comment say whose each decision is — the owner's with the date, else the team's — since an ADR is never rewritten after its merge (#263, #398). What changes what a person already has, such as a link that downloaded yesterday and fails today, is asked of the owner, not chosen.
- → A PR's title is a commit's subject: over 100 characters it fails commitlint's "Conventional title" check (#263). Count a title before `gh pr edit --title`.
- → A capture is read for paths and names before it is committed: one taken on a profile under the account's temporary folder showed the account's name in a public repository (#131). A capture's profile, and its download folder, live under the system's public profile.
- → A README's moving picture is a GIF outside `<picture>`, which GitHub wraps in its player, and it plays twice and stops on its last frame (NETSCAPE2.0's count 1), the owner's decision (#312, #313, 24 November 2026). Light and dark go as two images marked `#gh-dark-mode-only` and `#gh-light-mode-only`, and GitHub's own rendering (`gh api /markdown -f mode=gfm -f context=<repo>`) is read for `data-animated-image` before a body says it plays there.
- → The owner's choices given on the issue a PR delivers are logged in `docs/product/decisions.md` by that PR, with the decision each changes (#312, #190, #310, #221).
- → A rule that makes something proof is read against every answer that thing can give: "it proves the item as _Report_" was written of every Beta report, while its form also offers "Partly" and "No" (#319).
- → A document of state — the roadmap, the README, a runbook's "Not there yet" — writes in the present only what exists: "the ADR records it" of an ADR still to write, or a bare "Built and proven", reads as done (#29, #31). Write "has to" for what is still to do.
- → A rule added to a process is checked against every other rule that decides the same thing, searched for by the thing decided (when, where, "role"), not by the new rule's words (#17, #27, #31, #36, #157, #319, #375). The "so that" of a decision is a statement of its own, and is searched for too.
- → "No code changed" is not a reason to skip a gate: the gates run on every head, and who runs them is `review-flow.md`'s, "The gates" (#27, #187, #373).
- → What a PR body hands to a follow-up issue is in that issue before the body is posted, and a point of the issue a PR closes is delivered — the run that proves it named — or carried by a new issue first (#43, #44, #51, #52, #85, #86, #245, #246, #261, #302, #319, #347). Write the issue's list first, by opening every file the change could make stale, then copy it.
