# Gotchas — specs

For a change to a spec of any layer, a `testing/` folder or `apps/desktop/e2e/`, and for a mutation run or a probe. Lint holds fixed sleeps and hard-coded `\` separators in the specs themselves, `*.test.{ts,tsx,mjs}`, not in the helpers this file is also read for (`eslint.config.js`). Read with the general entries of [`.claude/gotchas.md`](../gotchas.md); each entry's story is in the issues it names.

- → A status region that is always there is found at once, before its answer: a spec that read its text from `findByRole('status')` failed one run in three (#138). Wait for the text (`vi.waitFor` on `toHaveTextContent`), not for the region.
- → playwright-core keeps a page `visible` under its Electron driver, also minimised or hidden (#138). Before blaming the runtime, run it without the driver — Electron started by itself, the page read over DevTools — and say in the PR what the driver cannot show.
- → A spec never polls a file the code renames onto: on Windows a reader makes the rename fail (`EPERM`), and specs failed one run in three, in the engine and in main (#137, #173, #280, #346). See what is kept through the store the code is given, main's log, or one read once the writer has ended; a write that can fail says so in the log.
- → A spec that changes `process.env` changes it for everything started after, and a spec that times out never reaches its `finally` (#173). Change it with `vi.stubEnv`, and undo it in `afterEach` (`vi.unstubAllEnvs`).
- → An E2E window takes the system's mouse as well as the spec's, and a real cursor crossing it ended a hover, 3 runs in 12 (#135). `launchScia` makes the window ignore the system's mouse (`setIgnoreMouseEvents(true)`).
- → A fix found while proving something else in the real app is still a rule without a spec (#21). Write its spec, seen failing against the old code, before the PR is opened.
- → A line taken away whole is not every attack on it: a wait made deaf to its signal, and a bound changed in value, survived where the deletion broke specs (#259). Attack a wait that must hear a stop by taking the signal away and a stated bound by changing its value — by hand where Stryker cannot (`docs/development/testing.md`, "Mutation testing") — and say which kind of mutant each count is of.
- → A spec is seen failing against the code it replaces, also when the code came first: an order claimed "by specs" had none (#32).
- → "By specs" in a test plan is checked by deleting what the line claims is held: with `autoFocus` removed, the suite was still green (#32).
- → A spec's premise is made, not assumed from the issue: a window at 720 px fitted on CI, a store's first write had always landed, a hundred failures had always ended before the first claim (#143, #244, #312, #346, #348, #349). Size the window the spec needs, wait for what the premise needs, print its numbers when it fails, and count what a store spared once it has finished.
- → What the engine says is not what the page draws, a quarter of a second later: rows still to be drawn moved a press 16 px off its button, in 6 of 91 E2E jobs (#268). A spec that measures, then presses, waits for what the page draws (`drawnCompleted`) and checks what is under the point before pressing (`pressedAt`).
- → Each place a guard is put is taken away on its own, and the one no spec catches gets a spec or leaves the PR: guards worn in one more place went with every spec green (#244, #261, #302, #347). A road "no host here can make" was made with the hosts at hand.
- → Playwright's `getByText` matches part of the text, whatever its case, and a notice that named a setting made a strict locator find two (#142). Search the E2E suite's locators for a sentence that names a control before the push; a locator that means a label says `exact: true`, or finds it by role.
- → A bound the issue sets on what a spec makes is held by that spec, and read in what it made before the body gives the number: a loop ran 11.4 s against a bound of 10 (#310, #312).
- → A loop a spec starts in the background has its rejection heard where it starts, and ends in the spec's own `finally`, before `useRun` closes the app, not through `run.keep` (#312).
- → A spec of rounding at `.5` cannot tell `ceil` from `round`: take a fraction under `.5`, where only `ceil` gives what is owed (#244).
- → What measures "again when X changes" — an observer, a `resize` listener — has a spec where only X changes (#244).
- → A bound in a timing spec is set against what the code does without the thing held: a pause passed in 980 ms under a one-second bound with the guard gone (#44). Make what is owed several times the bound, and see the spec fail with the guard taken out.
- → A spec written after its code is seen failing by taking the code's lines away one at a time, at every place a guard is reached from, the "obvious" ones too, and a spec that names two things has a case that fails for each (#44, #51, #52, #131, #136, #343, #347). A half proved through something that ends it anyway proves nothing: hold it with a case that ends nothing of it.
- → A list of mutants names the lines, run on every road that reaches each — any caller of a route, not the one screen — and a line no road reaches is taken out of the code (#32, #44, #53, #65, #86, #100, #136). A round's mutants are every line of its own diff, `npm run mutate -- --base <the round before's head>`, and the hand adds what Stryker cannot make, a guard's attack and a class that decides what is drawn among them (#137, #302; `docs/development/testing.md`, "Mutation testing").
- → A mutant can reach a real host: one of the line that points a run at its local host points the specs at the real one, and a run may have posted to `apidl.bunkr.ru` (#228); one that lets a link go "as it stands" fetches `bit.ly` (#263, #367). Every mutant runs behind the guard `npm run mutate` loads into every process and sees refusing first, a hand mutant too (#259, #286); a variant run in CI to see an E2E hold fail has none (`docs/development/testing.md`, "Mutation testing", "A hold seen failing in CI").
- → A network guard is proven against a reserved address, never a real host: `192.0.2.1` (TEST-NET-1, RFC 5737). A probe tries each road apart and destroys what it opened, since on its first run the guard is not yet known to work (#286).
- → A guard of the socket alone let `http` through: `http` hands its socket `path: null` beside a host, which a check of `path === undefined` read as a pipe (#386). A pipe's path is a string, and each road over the socket — `http`, `https`, `tls` — is tried on its own by the probe.
- → A value the page computes is checked to be in the form the spec parses before anything is computed from it: an `oklab(…)` read as rgb gave 18.92:1 for a placeholder near 3.5:1 (#246). Refuse any other form (`^rgb\(\d+, \d+, \d+\)$`), and set the variant in main (`nativeTheme.themeSource`), not in the runner.
- → A number in a spec's comment, and in the body that quotes it, is counted from the run, not from the setting: eight connections were configured and a file of 4 MiB made four (#44, #302).
- → A wait for something new waits until the last thing seen is not the old one, and says what must not happen by order, not by a count taken while requests are on their way (#136, #137, #138, #286). Slow the service before the thing that asks, stop a run by its own controls rather than `close()`, and run a spec of a wake with the wake taken out.
- → A rule a PR writes into its canon is read against every road of its own code, after the action as well as before: "the service's links are in no answer" was false of every answer once the download started (#263, #347). A spec of "never in an answer" reads every answer the feature gives, also once it has become something else.
- → A guard after an `await` needs an answer that ignores the abort, or no road reaches it (#263). A spec's fake answers by hand and stays deaf to the signal, and no `close()` waits for such an answer.
- → A bound in a spec is set well inside every limit that would end the thing by itself: a wait as long as the client's own answer limit let a removal's abort go with every spec green (#263).
- → A hand mutant or a probe made in the checkout under review failed other roles' runs (#135, #322, #144). `npm run mutate` mutates a copy; what it cannot make is made by hand in a worktree of its own (`docs/development/testing.md`, "Mutation testing").
- → A value built in a `describe` body is built when the file is collected, not when its spec runs: a code expired from collection read "9 min" (#292). Read the time from a clock the spec sets (`vi.setSystemTime` in `beforeEach`), and see the spec fail under a start delayed past its margin.
- → A spec that counts what the code does again when a bound falls counts the machine's load (#238). Hold what the spec means with a host that answers every attempt alike, and prove it with the spec's event loop held past the bound.
- → A limit of the code on the real clock races the start of what it limits, and a file written with `writeFileSync` exists empty before it is full (#163, #165). Put the adapter's timers on the spec's clock once the process said it started (`givenUpAt`), and write what a spec waits for beside it, then rename it into place.
- → A file written beside and renamed into place is written under a name of the writer's own, and the writer whose rename loses drops its own and leaves the other's (#306, #262). On Windows two renames onto one file at once refuse one (`EPERM`), which a probe on macOS cannot show (#309).
- → A host that sends slowly to give a spec time to act loses to a slow spec (#165, #302, #346). Hold the answer midway until the spec lets it go (`holdBuilds`, `UNFINISHED`), wait for what the code says it did, and hand the code a clock the spec moves (`now`).
- → A wait is not measured by the time the thing took: 900 ms read 2167 on a loaded run (#165). Read what the code hands out on its own clock, and see the mutant fail it.
- → A process started is not yet a process in place: `'spawn'` comes before the child has opened its folder (#174). A spec's holder says it holds — a line on its output, a file it writes — and the spec waits for that.
- → A Vitest `?raw` import of a `.css` file comes back empty: a spec that needs the stylesheet's text reads it with `node:fs`, from a workspace with Node types.
- → Two downloads added together race for the plain file name: a spec does not assume which gets `name.ext` and which `name (1).ext`.
- → A fake answer in a spec does not end when its request is aborted, as a real one does: a reader waiting on a stream is closed by whoever reads it (`reader.cancel()`), or the spec hangs (#45).
