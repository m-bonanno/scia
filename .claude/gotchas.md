# Gotchas — mistakes already paid for

Read the groups your change touches before a push. Add a `→` entry in the same PR when a mistake of that kind bites again.

## Tooling

- → `npm install` can leave `node_modules/electron/dist` empty while exiting 0. Symptom: `electron.exe` missing. Fix: `node node_modules/electron/install.js`.
- → `erasableSyntaxOnly`: no `enum`, no parameter properties, no namespaces. Use `as const` objects and plain fields.
- → Node runs the workspaces' TypeScript directly: imports carry the `.ts` extension, and a package's `exports` point at `src/`.
- → `@typescript-eslint/no-unnecessary-condition` reads a flag changed in a callback, or re-read after an `await`, as constant. Read it through a function (`#isStopping()`, `stopped()`), do not disable the rule.
- → Husky runs whatever hook a checked-out tree carries: `core.hooksPath` is `.husky/_`, whose wrappers run `.husky/<hook>` when the file exists. Checking out a contributor's branch puts their `.husky/post-checkout` there and runs it on this machine — `/team-review` said "check out the PR's branch" (#28). A fork's PR is read with `gh pr diff` and `git show`, or in a tree made with `git -c core.hooksPath=/dev/null worktree add`.
- → A branch is deleted after the merge is read back, not after the merge command: `gh pr merge --match-head-commit` takes the full SHA, refused a short one, and the `git push --delete` chained after it closed the PR it had not merged (#74). Read `gh pr view <n> --json state` first.
- → `@typescript-eslint/unbound-method` fires on `expect(object.method)` when the interface declares a method. Declare callbacks as properties (`readonly pause: (id) => void`).

## Formatting numbers

- → The editing tools of a session turn ` ` written in their text into the character itself, and so do PowerShell strings passed through them: three rounds of #101 put an invisible no-break space in a spec and in a component, which `no-irregular-whitespace` caught only in the component. In code, use `NBSP` from `lib/format.ts`; in a spec, write the escape with a script that builds its backslash, and check with `git grep -nP '\xa0'`.

- → Grouping depends on the locale's CLDR data, not on intuition: `en-US` writes `1,000`, while `it-IT` leaves a four-digit number ungrouped (`1000`). A spec expects what `Intl` says for the `LOCALE` of `@scia/contracts/locale`.
- → The unit is tied to its number with a non-breaking space, written as the escape `\u00a0`, never as the invisible character itself.
- → Testing Library normalises the white space of the text it reads, the non-breaking space included, but not of the string it is asked for: a spec finds a formatted amount with a regular expression (`/^10\.0\sMB\/s$/`), not with the string.

## Copy

- → A change of wording or of language is finished when a search of the whole tree for the old words finds nothing (`git grep -nE "[àèéìòù]"` caught what reading the diff did not), and every dialog was opened in the real app: a screen nobody opened is a screen nobody read.

- → A word given a new meaning is searched for in its old one, in the whole tree and not in the files the change touched: "theme" went to the palette and "variant" to light or dark, and "both themes" stayed in the PR template, in a role file and in the roadmap line beside the new one — `git grep -nIiE "(dark|light|either|both) themes?"` found the four (#52, the rule above a second time).

- → A sentence that names a cause is shown for that cause alone. One `catch` around a call that rejects in five ways said "choose a folder Scia can write to" to someone whose engine was restarting and who had chosen nothing: try a `catch` against every way the call rejects, and have the callee say which it was, as data (#38).
- → A sentence written for one code is checked against everything that code covers: "AllDebrid is not answering" was the text of a code that also means maintenance, an unknown answer and too many requests — it named one cause of four (#53: #38 again; #65 again, "refuses the key from this network" for a code that also means a sign-in awaiting confirmation). Write what is true of the whole group.

## Specs

- → What a component that stays mounted remembers is still there when it is shown again: Settings is never unmounted, and a refusal said in one visit greeted the next. Clear it when it opens, with a spec that closes and opens (#38).
- → A fix found while proving something else in the real app is still a rule without a spec: the run shows it once, and nothing holds it afterwards. Its spec is written, and seen failing against the old code, before the PR is opened: the message for a file that does not open went to review held only by a harness (#21).

- → `userEvent.dblClick` on a button that its first press replaces sends the second press to the element that is gone: the spec passes whatever the code does. In a browser the second press lands on the replacement, as a click whose `detail` is 2 — fire that (`fireEvent.click(button, { detail: 2 })`), and say what a harness proves: one that sends `clickCount: 2` over the DevTools protocol proves what the page does with a second press, not that a hand produces one (#32: a double click on the cross deleted unfinished bytes, and its spec would have been green). #131 again: a ready row's Start was replaced by Pause, a double click started and paused, and the specs pressed Start and never looked at what was drawn in its place. A control whose press changes what it does is one element whose label follows the state (`MainAction`), with the burst guard of `useOnePress`.
- → A guard written for the pointer is tried on the keyboard's twin: a key held down repeats the press, as clicks whose `detail` is 0, and one gesture asks and answers itself. `userEvent.keyboard('{Enter>5/}')` is the spec; `event.repeat` is the guard, for the key that presses and no other: refusing every repeat stopped a held Tab on the first such button of the list (#32: a held Enter ran "Run" and deleted unfinished bytes; then its fix broke Tab).
- → A guard put in a shared component reaches every user of it: "ignore the second click of a double click", right for a button that asks, swallowed the quick presses of someone clearing finished rows, each landing on the cross that slid under the pointer (#32). Ask what each user of the component does with the gesture.
- → A spec is seen failing against the code it replaces, also when the code came first: the order "mark, then look at the name" was fixed in one round and claimed "by specs" with none; the spec written in the next was run against the old order before it was believed (#32).
- → "By specs" in a test plan is checked by deleting what the line claims is held: with `autoFocus` removed, the suite was still green (#32).

- → A control that changes size or place when it is pressed is tried with the pointer where the control will be, not only where it was: "Run" is wider than "Open", grew under a double click made beside it, and the next click of that burst answered it (#32).

- → A bound in a timing spec is set against what the code does without the thing held, not against what it does with it: "a pause under a limit takes less than a second" passed with the wait deaf to the pause, because one read at the floor is a second and the unguarded pause took 980 ms. Make what is owed several times the bound, and see the spec fail with the guard taken out (#44).
- → A spec written after its code is seen failing by taking the code's line away, one at a time — also the ones that "obviously" hold: a read made "when the engine is reached, and again when it comes back" stayed green with the read made at mount only, because the spec's connection never changed (#44; #51, again). A spec whose comment names two things has a case that fails for each: "emoji where the beginning is cut, and where the end that is kept begins" held the beginning only, because in every name ten units from the end fell between two characters (#51, a third time). A guard reached from several places is taken away at each of them: the late read of Settings was held at the opening and at a change, and not after a folder was chosen, where every spec stayed green without it (#52). #131 again: the busy flag of the clipboard's reading was cleared after a read and at a turn off, and only the first had a spec.
- → A list of lines taken away names the lines, and a line no road of the specs reaches is not among the "caught": the plan said "each of the service's codes unmapped" and "the account asked at every listing", and two of those lines could be deleted with every spec green — a code the simulated service is never made to answer, and a line only an engine that read its key from the vault runs. Take the line away on each road that reaches it; a line no road reaches is taken out of the code (#53: the slips of #32 and #44, both again; #65 again). #86 again: "every line that decides something" was claimed of an encoder where the directory's height byte, the planes, the mask's byte and the rule "a bitmap below 256" could each go with every spec green. Take them away with a script that removes one line, runs the specs and puts it back, and count from what it printed. #100 again: the author's script took away what was easy to name, and the tech lead's found the two lines that keep yt-dlp from going back to an older signed build — "newer than the one in use", and a date read only from what the signature covers — each removable with every spec green. A guard's mutant is the attack it stops, not its deletion: `!==` for "newer", the unsigned part read for the date. And a fix in an adapter is taken away where it is used too: `main.ts` calling the old `open` kept 393 specs green. #136 again: a code's cancel at a disconnection was taken out as "no road reaches it" because the page offers none — and the API did (`POST /code` while connected, then `DELETE`). A road is any caller of the route, not the one screen; the fix there was to close the road (a code is refused while a service is connected), not to trust that nobody takes it.
- → The numbers of a run are read from that run's record, and a body that tells of several runs says which run each number belongs to: "two requests in the whole run" was the count of the last run, beside sentences from an earlier one that had made four (#53: #44 again).
- → A number in a spec's comment, and in the PR body that quotes it, is counted from the run, not from the setting: eight connections were configured, and a file of four megabytes made four (#44).

- → Two asks of the same thing answer in the order they like. Settings read the engine at every opening and kept whatever came back: a change made while that read was on its way was undone on screen when the read answered after it — the page went back to the theme of before, with the engine keeping the new one. No person is that fast; a harness on a window the system had put in the background was. An answer is kept only when nothing was asked after it, and the spec holds the late answer back by hand (#52).

- → A way back is not offered beside something that cannot be taken back: "Cancel" stayed pressable while a key was being checked, the key was kept all the same, and a refusal that came back was drawn under a row with no field (#53). Try every control of a form while its request is on its way. #136 again: a code asked for kept coming after Cancel, after "Use an API key" and after Settings closed, replaced the key's field, and was waited for ten minutes by an engine whose cancel had arrived before the code existed — on the page and in the engine. Every ask carries its turn; what answers an ask that is no longer the last is dropped, and told to forget what it brought.

- → Whether to hand on a focus is decided when the control leaves, from where the focus is then, never from a flag set at the press: "Start all" set one at its press and kept it through a refused request, or a new ready row arriving with it, and a later, unrelated leave pulled the focus from a row's own button to the filters (#131).
- → A reading that marks a baseline — "what was there when it started" — is tried with that reading refused, answered empty, and answered late by a turn before an off and on. The clipboard's reading took a link copied before the switch was turned on in all three ways, with every spec green; and Electron 44 answers `''`, not a rejection, for a clipboard it cannot open (#131). The baseline belongs to its turn, and nothing is offered until a read of that turn has found it.

## Docs and runbooks

- → A capture is read for paths and names before it is committed: a Settings capture taken on a scratch profile under the account's own temporary folder showed that folder, and the account's name with it, in a public repository (#131). A capture's profile, and its download folder, live under the system's public profile.

- → Text with backslashes written through a script's string loses them: in a JavaScript string `\P` is `P`, and a runbook said `%LOCALAPPDATA%Programsscia` — then the same slip broke a regular expression in the fix (#111). A Windows path or a regular expression goes into a file with the editor, not through `node -e`, a heredoc or `sed`, and the file is read back for it (`git grep -n 'Programs\\'`). #100 again, four times in one branch — `[\w.-]` became `[w.-]`, `\/releases\/` a comment, `resources\tools` a tab — each caught by a spec or a refused replacement, none by reading. #136 again, twice: a spec's address meant to hold `\\@` was written through `sed` and held `\@`, caught by `no-useless-escape` at the commit, not by reading; and this very line, written through a heredoc, lost both of its backslashes.
- → Where a document of state — the roadmap, the README, a runbook's "Not there yet" — names what vouches for something (an ADR, a spec, a run, a record), the present is for what exists: "the ADR records it", "a spec holds that" for one still to write is a "done" nobody did. Write "has to" (#29, twice in one PR, the second time in the commit that fixed the first). A bare participle does the same: "Built and proven against a simulated service" reads as done beside lines where "Written, covered by specs" means it (#31). A planned item written in the present ("Choosing the folder") is not this.
- → A rule added to a process is checked against every other rule that decides the same thing: size was added to how the roles of a review are chosen, and the rule on a commit pushed after the approval still chose them by area alone (#27 — the slip of #17, a second time). Search the runbook for the thing decided ("role", "reviews again"), not for the words of the new rule. The roadmap is no different: "Linux comes after the first stable release" was added above a line that still listed Linux among what that release waits for (#31). And the "so that" of a decision is a statement of its own: "public shortly before the release, so that automatic updates are proven on a beta with installers" stood above a line that still called the stable release the first run of the installers job (#36). Search for when and where the thing happens, not for the words of the decision.
- → "No code changed" is not a reason to skip a gate: the five are run on every head — by the author, by the tech lead, and by CI; on a fork's PR by CI alone (`review-flow.md`, "A pull request from outside") — and the PR body carries their numbers (#27).
- → What a PR body gives to a follow-up issue is in that issue before the body is posted: "not verified (#43)" named, twice in one review, something #43 did not carry — the open list of a menu, then HTTPS — and a body stops being read the day its PR merges (#44; #51, again). The roadmap's "Not seen" is the same list: written from memory it had two items where the body had nine (#52). #86 again: the roadmap and the design README handed "the shortcuts as Windows draws them" to #85, which did not carry them, and the window in Alt+Tab to nothing. Write the issue's list first, then copy it.

## Engine

- → A wait put in front of every download is measured against a service that never answers, and against one that refuses, before it is called harmless: the public list of #49, asked three times at ten seconds each, held a direct link for 33 s with no service connected — and every spec was green, because the simulated service always answered at once (#72). One request, a short bound, a list in hand used while it is read again. #104 again: the E2E suite started the app naming no service, so every pasted link waited on AllDebrid's real public list — the suite left the machine, and the speed limit's spec stayed green with the limit taken away, the three-second wait passing for it. Every run of the real app names a simulated service, also when it connects none (`launchScia` does), and a timing is counted from where the thing measured begins.
- → A question to the system is tried for its "no", on the system it will run on: `access(folder, W_OK)` has none on Windows, where it says yes for every folder that exists — read-only attribute, denying access list, `C:\Program Files`. What has to be possible is proven by doing it: make a file, remove it (#38).
- → A name from a host that decides something is read as the system reads it, not as Scia numbers a copy: `setup.tar.exe` and a bare `.cmd` were not programs to a function that took `.tar.exe` as one extension and a leading dot as none. And a list that is a safety rule is drawn from the system (`PATHEXT`, `assoc`/`ftype`), not from memory: `vbs`, `js`, `hta`, `pif`, `lnk` run at a press (#32).
- → A vitest `?raw` import of a `.css` file comes back empty. A spec that needs the stylesheet's text reads it with `node:fs`, from a workspace that has Node types.
- → Two downloads added together race for the plain file name: a spec must not assume which one gets `name.ext` and which `name (1).ext`.
- → `IncomingMessage` must be destroyed, or drained, on every path that does not read it to the end: a redirect, a refused status. Otherwise the socket stays busy.

- → A wait added inside a loop is tried against every timer that already watches that loop, at the largest numbers the settings allow. A connection that waits its turn under a speed limit is silent to its socket: the 30 s idle timeout cut it and asked the host again, for every read, from 160 connections at 256 KB/s — and no spec with one download could see it (#44).
- → A limit is paid before the read, not after it, and a read is made only against room that covers it. Paid after, a loop that books past its "is this the end?" never booked the last read — a file that arrives in one read was not limited at all — and, once that was mended, every connection still took its first read unpaid and left it owed when its download was removed: 10 MB at once and then 40 s without a byte, at the most Settings allows. Paid before, but only when nothing was left of the last booking, the couple of hundred bytes an answer's headers leave let a whole read through: twice the limit while connections opened (#44).
- → A rate is proven against a host that sends as fast as it is read, and counted in bytes the engine took — not in bytes written, which lag, and not in the speed shown. A test host that pauses between pieces hid a limit passed twofold, in the specs and in the real app (#44).
- → A list of values is tried at both ends, and over the transport people use. Every run of the speed limit sat between 256 KB/s and 2 MB/s, over plain http; at 25 MB/s a read's turn is two milliseconds, a timer under sixteen takes sixteen on Windows, and a wait that ended late was lost for good: a download got a third of its limit, on every head of the PR, and less over HTTPS, where a read is a quarter the size — until the third round measured it (#44).
- → A guard that is taken away is searched for everything else it was guarding. The idle timer that left the socket was also what ended a redirect's drain and an answer nobody read (#44).
- → A word from outside is not looked up in a plain object: `FAILURE_OF[code]` found `constructor` and `toString`, which every object has, and a service's code of that name became a refusal with no code, where the rule says "a code Scia does not know". A `Map`, or `Object.hasOwn` (#53).
- → A number from outside is bounded before it becomes a date, and bounded by what the contract on the other side takes: `new Date(seconds * 1000).toISOString()` throws for a number no calendar holds, and a throw that is not the adapter's own error crosses the API as a 500; bounded at the last second a `Date` holds, it wrote `+010000-…` for the years past 9999, which the page's `z.iso.datetime()` refuses — a service connected, and a page that could neither say so nor disconnect it (#53, twice). #136 again: a code's `expires_in` became `expiresAt` unbounded, a 500 for one lifetime and a date the contract refuses for another.
- → Two changes of one thing kept outside the process are made one at a time, and one that was given up on is undone: a write to the vault that main finished after the engine stopped waiting left a key the person had been told was not kept (#53; #65 again, twice — the second time the kept list of hosts, written while a disconnection removed it: its write now waits its turn with connecting and disconnecting).
- → A guard read before an `await` is a guard of the moment before it. A code was refused while a service was connected by reading the key once, before AllDebrid was asked; a key being checked at that moment was kept while the code came, and the code was then waited for beside it — confirmed with another account's key, it replaced the key (#136). Whatever decides after the wait is read after it, or something that changes it during the wait moves a turn the waiter compares.
- → Something the engine can do without is opened so that it never fails the engine's start: the yt-dlp updater, awaited before the engine listened, threw on a leftover build a running yt-dlp held, and the engine exited at every restart until Scia gave up — no download at all for a housekeeping step (#100). Each step that can fail is caught and logged, and the piece as a whole falls back to running without it, with a spec in which it cannot open and an E2E spec in which the app still starts.
- → A listener added to a signal that has already aborted never fires: `addEventListener('abort')` is not told of the past. A wait that begins after a stop — the stop landing during an `await` just before — waits for whatever else it listens to, and a shutdown hung behind it (#100). A wait checks `signal.aborted` before it listens, with a spec in which the stop comes first.
- → Nothing that paces or times out runs on `Date.now()`: the system's clock steps. `performance.now()` does not (#44).
- → A simulated service written from the documentation is the documentation, not the service. Every spec and every run of #65 against it was green; the first run against the real AllDebrid got a direct link answering ranges with 204, and a first byte with a 200 that carried only that byte — neither in any documentation, both gone minutes later. A service is tried for real before its "done", with whoever owns the account, and what it showed becomes an option of the simulated host (`noContent`, `firstByteAs200`). The same holds for a library read ahead of a run: electron-updater's source said a repository with no stable release fails with "please ensure a production release exists", and the packaged app against this repository got "No published versions on GitHub" — so "nothing to take" is read from the error's code, which the run showed, not from words the source suggested (#82).
- → A program the engine starts is given an environment built from nothing, and is tried inside the app, not from a shell. Spawned with the engine's own, yt-dlp got the API's token, and no `TEMP`: the engine's environment is main's whitelist, and yt-dlp's build stops at once without a folder to unpack itself into ("Could not create temporary directory"). Every spec was green — the fake ran with the spec's environment — and so was yt-dlp run by hand; the app failed every page (#89). The environment is built in the adapter, and a spec reads what the program was given.
- → A screen is read only once nothing secret is on it: reading a terminal tab to learn how a run ended showed the key the owner had typed on it two lines above. A key goes into a shell from the clipboard (`$env:… = Get-Clipboard`), and a run's outcome is pasted by the person, not read off their screen (#65).
- → A harness that runs the local hosts of a run in its own process never waits synchronously: a loop of `execFileSync` that watched for a process held the event loop, the hosts answered nothing, and the app's download sat at "Connecting…" while AllDebrid's list "did not answer" — the app was fine (#100). Use `execFile`, awaited, or put the hosts in a process of their own.

## Electron

- → A pixel read from the screen is the pixel of whatever is on top. A harness that proved the window's own colours with `CopyFromScreen` was right nine times and then read another window's purple nine times, when something else came to the front. `PrintWindow` with `PW_RENDERFULLCONTENT` reads the window as the system composes it, covered or not (#52).
- → A window that another window covers stops drawing: a transition stays where it was, and a capture taken then shows half of two variants — rows in the light variant on a dark page, which no person ever sees. A harness that captures starts Electron with `--disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows --disable-renderer-backgrounding`, and takes no capture before what it shows has settled: a row is the colour of its token (#52). #136 again: `two-ways-to-connect.png` was taken the moment the row appeared, and its main button sat two thirds of the way between the light and the dark tokens — read in its pixels by the product designer, not by its author. A harness waits for the transitions to end (their duration, or `getAnimations()` empty) before every capture.
- → A harness closes Settings with its button, or waits for the dialog's `close` event before it presses again: the page learns that Settings closed only from that event, so a press sent in the same turn as a close is lost, and in a window that is not drawing the event does not arrive at all — Settings then opens at no press until it does (#52; the app's side is #67).
- → Two harnesses on one debugging port drive the same page: one that hung on a dialog nobody answered was still alive when the next started, attached to the new app and added every download a second time. End the old one — and bound every `fetch` to the port with a timeout — before starting another (#52).

- → A Start menu shortcut a harness makes so that a development build's notifications show carries Scia's app id, and the taskbar resolves the installed Scia through it: with an `Electron.lnk` pointing at a worktree's `electron.exe`, the installed app's button was named "Electron" (#81, #85). A harness that makes such a shortcut removes it when the run ends; a run that reads the taskbar first reads `Get-StartApps` for `app.scia.desktop`.
- → A script Electron runs ends on every road. `app.whenReady().then(async …)` with no rejection handler only logs the rejection and keeps Electron alive with its hidden window, and a `spawnSync` with no `timeout` waits for it for ever: `npm run icons` on an SVG that did not decode never ended, and left its scratch folder (#86). A handler that calls `app.exit(1)` with a message, a time limit on the spawn, and a run with a broken input and one with the limit lowered.
- → A screen that is locked has no taskbar to capture: `CopyFromScreen` returns the lock screen, flat. Look for `LogonUI` before believing a capture; the shell's icons are read without the screen (`IShellItemImageFactory`, `Icon.ExtractIcon`, `WM_GETICON`) (#81).

- → A page's `window.close()` destroys the window at once: Electron does not emit a preventable `close` for it. A harness that wants what the X does follows `docs/development/testing.md`, "Proving the real app".
- → A harness's start that fails leaves the app it launched running on its profile, and on Windows playwright-core's `app.process()` is the shell that started Electron: `kill()` ends the shell, its exit event comes at once, and Electron — main blocked on the error box of an engine that never started — stays, holding the profile (#104). End main by the pid it reports (`process.pid` through `app.evaluate`) with its tree (`taskkill /T /F`), wait for that pid to be gone, and try it on a start that fails. Ask for that pid at once after the launch, with a bound, and fall back to the shell's tree: main stops answering `evaluate` once the error box is up, a fraction of a second after the launch returns.
- → A debugging port answers before the window has a page: a harness waits for a `page` target, not just for the port.
- → Node's `fetch` ends an answer whose body says nothing for 300 s, and a run shorter than the longest timer under a thing cannot show it: main's stream from an idle engine was cut every five minutes, and every run of the PR lasted one. A thing that lasts as long as the app is left alone for longer than every timer under it (#51).
- → A holder made for something shown once does not fit something shown many times: one variable kept the last notification, and by the comment beside it a notification nobody holds is collected with its click. Every one that can still be clicked is held (#51).
- → An end told from the one before only by a list in between is not told when the list does not come: a download that failed, was tried again and failed again within the quarter of a second between two lists failed once, to main. Say the limit, or have the source say when it happened (#51, #55).
- → A conflict resolved in an adapter keeps both sides' lines and their order: the merge of the themes put main's ear on the engine after an `await` of the theme, and a download that ended in that wait — up to two seconds — was taken for one that had already ended. Nothing failed, and no spec of the adapter could see it; the backend engineer measured it with an engine slow to say its settings (#51).
- → `BrowserWindow.isVisible()` is false for a minimised window on Windows: "hidden in the tray" is not shown _and_ not minimised. A notification told a person whose window was on the taskbar that Scia was in the system tray; the run in the real app showed it, no spec could (#45).
- → `BrowserWindow.isFocused()` is what the window believes, not what the system says: on Windows a window shown while another is in use believes it is focused until it has really been used once and left. A notification meant for "not in front" stayed silent for a Scia that opened behind someone's work. A harness that wants a window in front, or not, reads the system's foreground window; it does not assume its own request worked — the author's could not take the focus from Scia in three ways, and reported the case as held elsewhere (#51, #62).
- → A fake answer in a spec does not end when its request is aborted, as a real one does: a reader that waits on a stream is closed by whoever reads it (`reader.cancel()`), not left to the request's signal. The specs of main's ear on the engine hung until it did (#45).
- → A very long profile path breaks Chromium's GPU cache (`The filename or extension is too long`). Harmless in a scratch folder; a sign to shorten the path, not a bug of the app.
- → Over the DevTools protocol, Enter presses a focused button only when its `keyDown` carries `text: '\r'`: without it the key arrives and nothing is pressed, and the harness proves nothing while looking as if it had.
- → A real double click over the DevTools protocol is two `mousePressed`/`mouseReleased` pairs at the same point with `clickCount` 1, then 2: `element.click()` from the page arrives with `detail` 0 and takes the roads a pointer never takes.
