# Gotchas — mistakes already paid for

Read the groups your change touches before a push. Add a `→` entry in the same PR when a mistake of that kind bites again.

## Tooling

- → `npm install` can leave `node_modules/electron/dist` empty while exiting 0. Symptom: `electron.exe` missing. Fix: `node node_modules/electron/install.js`.
- → `erasableSyntaxOnly`: no `enum`, no parameter properties, no namespaces. Use `as const` objects and plain fields.
- → A session's scratchpad folder can be shared with other sessions that work at the same time: a commit message written there as `commit-msg.txt` held another session's text when `git commit -F` read it, and a commit went in under the wrong subject (#182). Write such files in a folder named for the branch, and read the commit back (`git log -1`) before going on.
- → Node runs the workspaces' TypeScript directly: imports carry the `.ts` extension, and a package's `exports` point at `src/`.
- → `@typescript-eslint/no-unnecessary-condition` reads a flag changed in a callback, or re-read after an `await`, as constant. Read it through a function (`#isStopping()`, `stopped()`), do not disable the rule.
- → Husky runs whatever hook a checked-out tree carries: `core.hooksPath` is `.husky/_`, whose wrappers run `.husky/<hook>` when the file exists. Checking out a contributor's branch puts their `.husky/post-checkout` there and runs it on this machine — `/team-review` said "check out the PR's branch" (#28). A fork's PR is read with `gh pr diff` and `git show`, or in a tree made with `git -c core.hooksPath=/dev/null worktree add`.
- → A branch is deleted after the merge is read back, not after the merge command: `gh pr merge --match-head-commit` takes the full SHA, refused a short one, and the `git push --delete` chained after it closed the PR it had not merged (#74). Read `gh pr view <n> --json state` first.
- → A squash merge left to GitHub writes every commit of the branch into its body, and semantic-release's notes list each issue that body names: the notes of `v1.0.0-beta.30` said "closes #99" six times, one per commit that ended "(#99)", and `.18`, `.20` and `.29` did the same (#249). Merge with `--body "Closes #N"` — and the `BREAKING CHANGE:` footer when the change is breaking, or the line `This reverts commit <sha>.` for a revert, since the squash's body is the one place semantic-release reads either (`release-flow.md`, #114); notes already published are mended by their text, never their tag.
- → Git Bash says an exit code modulo 256: an installer that ended with 1638 read as 102 in `echo $?` (#172). A spec reads the code from Node (`execFile`'s `error.code`), a person from PowerShell (`(Start-Process … -Wait -PassThru).ExitCode`).
- → `@typescript-eslint/unbound-method` fires on `expect(object.method)` when the interface declares a method. Declare callbacks as properties (`readonly pause: (id) => void`).
- → `wc -m` counts bytes in a shell that sets no locale, as a session's shell does: #319's body gave `apps/server/CLAUDE.md` 48,583 "characters" where it had 48,370 — each `—` and `→` is three bytes — and a reviewer's check confirmed the bytes as characters. Count characters with `LC_ALL=en_US.UTF-8 wc -m`, or with Python's `len` on the decoded text; Node's `length` counts UTF-16 units, which are characters only while none lies outside the BMP.

## Formatting numbers

- → The editing tools of a session turn ` ` written in their text into the character itself, and so do PowerShell strings passed through them: three rounds of #101 put an invisible no-break space in a spec and in a component, which `no-irregular-whitespace` caught only in the component. In code, use `NBSP` from `lib/format.ts`; in a spec, write the escape with a script that builds its backslash, and check with `git grep -nP '\xa0'`. #172 again, with another invisible character: a soft hyphen (U+00AD) landed inside a name in `apps/desktop/CLAUDE.md`, where no linter reads. Search the whole diff for both before a commit: `git diff | grep -nP '\x{00A0}|\x{00AD}'`. #228 again, in the engine: the escape `' '` written with the editing tool landed as the character itself in a map of HTML entities, where neither the linter nor a spec reads; the diff's search found it before the push.

- → Grouping depends on the locale's CLDR data, not on intuition: `en-US` writes `1,000`, while `it-IT` leaves a four-digit number ungrouped (`1000`). A spec expects what `Intl` says for the `LOCALE` of `@scia/contracts/locale`.
- → The unit is tied to its number with a non-breaking space, written as the escape `\u00a0`, never as the invisible character itself.
- → Testing Library normalises the white space of the text it reads, the non-breaking space included, but not of the string it is asked for: a spec finds a formatted amount with a regular expression (`/^10\.0\sMB\/s$/`), not with the string.

## Copy

- → A change of wording or of language is finished when a search of the whole tree for the old words finds nothing (`git grep -nE "[àèéìòù]"` caught what reading the diff did not), and every dialog was opened in the real app: a screen nobody opened is a screen nobody read. #152 again: Settings stopped offering the extension's code, and the extension's own options page and its "wrong code" message still sent the person to Settings' "Browser extension" — a section removed is searched for by its name in the whole tree, the other apps included.

- → A word given a new meaning is searched for in its old one, in the whole tree and not in the files the change touched: "theme" went to the palette and "variant" to light or dark, and "both themes" stayed in the PR template, in a role file and in the roadmap line beside the new one — `git grep -nIiE "(dark|light|either|both) themes?"` found the four (#52, the rule above a second time).

- → A sentence that names a cause is shown for that cause alone. One `catch` around a call that rejects in five ways said "choose a folder Scia can write to" to someone whose engine was restarting and who had chosen nothing: try a `catch` against every way the call rejects, and have the callee say which it was, as data (#38).
- → A sentence written for one code is checked against everything that code covers: "AllDebrid is not answering" was the text of a code that also means maintenance, an unknown answer and too many requests — it named one cause of four (#53: #38 again; #65 again, "refuses the key from this network" for a code that also means a sign-in awaiting confirmation). Write what is true of the whole group. #138 again: the panel of the account said "could not be asked just now" for a refused key, a banned account and a network refused — AllDebrid was asked, and said no — and asked again every five seconds; each now has its sentence, and what asking cannot mend stops the asking. #228 again, in the engine: `ALBUM_LINK_FAILED` ("the link the site gave no longer works") wrapped every `HTTP_STATUS` of a Bunkr file, and `HttpSource`'s `HTTP_STATUS` also covers a busy server (5xx, 429, 408, 425, a 204) and a range ignored (a 200) — a busy server was told its link was dead. A code that wraps another is mapped by what the wrapped one says of the cause (`retryable`, the status), never by the code alone. #303 again, in a count: "some of the links you pasted" was chosen by counting the batches the engine refused, and a batch lost to a dropped connection was not counted — nothing taken, and the notice said some was. A count that chooses a sentence counts what the sentence says: here, everything not taken, whatever the cause.

## Specs

- → A status region that is always there is found at once: `findByRole('status')` returned the empty region before the answer filled it, and a spec that read its text from it failed one run in three (#138). Wait for the text (`vi.waitFor` on `toHaveTextContent`), not for the region.
- → A live region that is `display: none` while it is empty is outside the accessibility tree when its text arrives, and an announcement that arrives with its region is often not made: `empty:hidden` on the panel's status did that, and jsdom, which applies no CSS, could not see it (#138). Check where styles exist — the E2E suite reads `getComputedStyle` — and keep the region drawn (`empty:py-0`).
- → playwright-core keeps a page `visible`: under its Electron driver, `document.visibilityState` stayed `visible` after the window was minimised, and after it was hidden, and a spec of what a hidden window does could not hold it (#138). The app started by Electron itself, main reached through `--inspect` and the page read over DevTools with `Runtime.evaluate` alone, said `hidden` both ways, as Electron's documentation does. Before blaming the runtime, run it without the driver; and say in the PR what the driver cannot show.
- → One thing reached by two roads under two names is compared under both before it is added: a magnet pasted is known by its torrent's hash, one taken from the account by AllDebrid's id, and the same torrent was in the list twice, its files downloaded twice, in either order (#138).
- → On Windows a file another process has open cannot be renamed onto: a spec that read `state.json` every 10 ms, to see a save, made that very save fail (`EPERM` on the rename, logged as `state_not_saved`) one run in three, and timed out (#137). A spec sees what the engine keeps through the store it is given (a `StateStore` that records each `save`), never by polling the file the store renames onto. #173 again: a spec polled the file to see a removal, failed one run in three after its full wait, and nothing saved again; it closes the manager, which waits for the last save, and reads the file once. #280 again, in the E2E suite and in main: the spec of the theme at the next start read `theme.json` every 10 ms until it held the new theme, and main's one write of it failed on the rename — silently, as `RememberedTheme` caught it and said nothing — so the spec waited its 30 s for a file that never changed, in 5 of the 51 E2E jobs from its first failure on (a probe here: 6 renames of 200 failed `EPERM` under a reader at 10 ms). Main now logs each write, `theme_kept` once it landed, `theme_not_kept` with why; the spec waits for that line and reads the file once, after the quit. A file of main's that a spec must see is seen through main's log or after main has ended — and a write that can fail says so in the log.
- → A spec that changes `process.env` changes it for everything the code under test starts after, and a spec that times out never reaches its `finally`. Pointing `SystemRoot` nowhere to make `taskkill` fail also broke the fake yt-dlp it started on CI's runner, and the next spec inherited it (#173). Change it at the moment it is read, with `vi.stubEnv`, and undo it in `afterEach` (`vi.unstubAllEnvs`).
- → A key held down repeats onto whatever the first press gives the focus to: Enter held on a notice's ×, guarded only on the ×, went on to send the field's unsent links and to close Settings once the last notice was gone. The guard is armed by the press and swallows the repeats wherever they land until the key is let go — of Enter alone, a held Tab walks on (#135). #136 again, the same day: Enter held on "Connect with a code" went on to press "Open AllDebrid" seven times — seven pages in the browser — and, with no main, Cancel and "Connect with a code" in turn, four codes asked of AllDebrid. A row whose presses move the focus arms the guard from the row, not from each button. Again in #157: the "Update to …" button opened a question whose first focus was "Restart now", and a held Enter restarted Scia; the guard is armed from the whole of what moves the focus — the button and its popover — and the first focus goes to the least consequential answer. #138 again: the panel's Close hands the focus to the button that opens it, and a held Enter opened it again.
- → An E2E window takes the system's mouse as well as the spec's: a hover the spec held for seconds ended when the real cursor crossed the window, 3 runs in 12. `launchScia` makes the window ignore the system's mouse (`setIgnoreMouseEvents(true)`) (#135).
- → What a component that stays mounted remembers is still there when it is shown again: Settings is never unmounted, and a refusal said in one visit greeted the next. Clear it when it opens, with a spec that closes and opens (#38).
- → A fix found while proving something else in the real app is still a rule without a spec: the run shows it once, and nothing holds it afterwards. Its spec is written, and seen failing against the old code, before the PR is opened: the message for a file that does not open went to review held only by a harness (#21).

- → `userEvent.dblClick` on a button that its first press replaces sends the second press to the element that is gone: the spec passes whatever the code does. In a browser the second press lands on the replacement, as a click whose `detail` is 2 — fire that (`fireEvent.click(button, { detail: 2 })`), and say what a harness proves: one that sends `clickCount: 2` over the DevTools protocol proves what the page does with a second press, not that a hand produces one (#32: a double click on the cross deleted unfinished bytes, and its spec would have been green). #131 again: a ready row's Start was replaced by Pause, a double click started and paused, and the specs pressed Start and never looked at what was drawn in its place. A control whose press changes what it does is one element whose label follows the state (`MainAction`), with the burst guard of `useOnePress`.
- → A guard written for the pointer is tried on the keyboard's twin: a key held down repeats the press, as clicks whose `detail` is 0, and one gesture asks and answers itself. `userEvent.keyboard('{Enter>5/}')` is the spec; `event.repeat` is the guard, for the key that presses and no other: refusing every repeat stopped a held Tab on the first such button of the list (#32: a held Enter ran "Run" and deleted unfinished bytes; then its fix broke Tab).
- → A guard put in a shared component reaches every user of it: "ignore the second click of a double click", right for a button that asks, swallowed the quick presses of someone clearing finished rows, each landing on the cross that slid under the pointer (#32). Ask what each user of the component does with the gesture. #138 again, in the engine: "not premium" mapped to 422 in the API's one error handler for the account's magnets also turned a link's refusal to a key into 422, which the canon answers 502; the mapping lives with the routes it is for.
- → A line taken away whole is not every attack on it: the fixes of round 1 of #259 counted `await sleep(waitMs, undefined, { signal })` as held — without the line, specs broke — while the same wait made deaf to its signal broke none, and a pause would have hung for the minute a site may ask; `return 0` in the schedule of waits survived too, because every spec injects its own delay. A wait that must hear a stop is attacked by taking the signal away, a stated bound by changing its value, and a body says which kind of mutant each count is of.
- → A spec is seen failing against the code it replaces, also when the code came first: the order "mark, then look at the name" was fixed in one round and claimed "by specs" with none; the spec written in the next was run against the old order before it was believed (#32).
- → "By specs" in a test plan is checked by deleting what the line claims is held: with `autoFocus` removed, the suite was still green (#32).

- → A spec's premise is made, not assumed from a sentence of the issue: "at 720 px Settings scrolls" came from #143's text, and on CI's runner it fits at 720 — the spec of #244 failed at its premise on two heads and proved nothing of what it was for. Size the window the spec needs (`setContentSize`, waiting for `innerHeight`; the protocol's viewport where the runner's screen is smaller) and have the premise print its numbers when it fails. It bit again in #312: the README's loop gave the page a viewport of 760 while the window stayed wider, and the title bar, laid out by the window's width, lost Settings and the speed in every frame (round 2). The window is sized, and the spec holds Settings inside the page and the page no wider than the window.
- → What the engine says is not what the page draws: the engine's list reaches the page at most four times a second, so a spec that waited for `allCompleted` (the engine's answer) measured rows the page could still draw downloading, a quarter of a second behind (#268). A row drawn completed afterwards loses its bar — 16 px — and every row in view under it moves up, from under a press aimed 10 px into a 32 px button: the press landed beside it and nothing was removed, in 6 of the 91 E2E jobs from its first failure on, the click and the tap alike. A headless probe of the built page on the engine under Node measured before the page had drawn every row in 45 rounds of 60, and in one the button moved 48 px and the point fell on the row; waiting for the page, 60 of 60 held still. A spec that measures, then presses, waits for what the page draws (`drawnCompleted`), and checks what is under the point just before pressing (`pressedAt`), so that a miss says where it landed rather than timing out on what the press should have done.
- → Chromium keeps a focus Tab moves out of an area's scroll padding, and leaves one the page moves itself (`element.focus()`) where it is when it is already in the scrollport — under the notices (#244). Playwright's `locator.focus()` is the page's road, and passed only because its target started out of sight. A spec of where a focus lands first puts its target where the guard matters — in the scrollport, under what covers it — and takes both roads.
- → Room bought with padding grows what is sized by its content: a centred dialog that fits grew by the notices' height and re-centred, moving under the pointer that had just pressed in it, where the notices covered nothing (#244). Room is bought only where the cover is, and a spec measures that what is not covered does not move.
- → A rule worn in one more place is a line no spec reaches until one does: the account's panel got the notices' room beside the list and Settings, and could lose it with every spec green (#244). Each place a guard is put is taken away on its own, and the one no spec catches gets a spec or leaves the PR. #261 again: a new token's name for Tailwind (`--color-paused` in `styles.css`), the link between its value in `themes.css` and the class a component wears, could go with every spec and the build green — Tailwind drops a class it does not know without a word, and the paused bar drew nothing; a spec now holds every token to its name, and the E2E suite reads the bar's colour in the built app.
- → Playwright's `getByText` matches a part of the text, whatever its case: a notice that names a setting ("Scia could not change the number of simultaneous downloads") made `getByText('Simultaneous downloads')`, the E2E suite's sign that Settings was drawn, find two elements, and a strict locator failed the captures' spec on CI (#142). A sentence that names a control is searched for in the E2E suite's locators before the push. A locator that means a label says `exact: true`, or finds it by role.
- → A PR that closes an issue cannot hand part of it to "before the issue is done": #244's body said the captures were still to be taken before #143 was done, beside `Closes #143` — the merge would have closed what was left with nothing to track it. Deliver it, or put it in an open issue first and name that issue. It bit again in #312: the social preview, a setting the owner uploads by hand, was left to "after the merge" beside `Closes #310`; a step of the owner's is done and read back before the approving verdict, its box ticked in the test plan.
- → A bound the issue sets on what a spec makes — a loop of 5 to 10 seconds — is held by that spec, and read in what it made before the body gives the number: #312's loop ran 11.4 s against #310's bound, and the body reported 11.4 s without the bound beside it. The spec now fails a loop outside it.
- → A loop a spec starts in the background has its rejection heard where it starts, and is ended in the spec's own `finally`, before `useRun` closes the app: #312's capture loop, left running when a wait failed, rejected unheard once the app was closed, and Vitest's "Unhandled Rejection" named `page.screenshot` beside the real cause. Not through `run.keep`: kept things are closed after the apps.
- → A handler on every focus runs for the focus a pointer gives too, at its press: Chromium focuses a button at `mousedown`, and #244's root scrolled it clear of the notices before `mouseup` — the press landed elsewhere and the click was lost, beside the notice, where nothing covered the button. Every E2E spec had reached its control with `locator.focus()`. A guard on focus is tried with `page.mouse.click` where it acts, and leaves the pointer's own focus alone (`pointerdown` in the same turn).
- → A pointer is a mouse, a pen and a finger, and they do not send their events in one order: a tap's `pointerdown` and `pointerup` come as the finger lands and lifts, and its `mousedown`, which gives the focus, a task or more later. #244 marked the press at `pointerdown` with a 0 ms timer and passed every mouse spec; the frontend engineer lost 13 taps of 15. Mark a press with the event that comes in the task of what it guards (`mousedown` for the focus it gives), and try a guard of "the pointer" with a tap too (`Input.dispatchTouchEvent` with touch emulation on).
- → `getComputedStyle(element).maxHeight` of the UA's `calc(100% - 6px - 2em)` is the string `calc(100% - 38px)`, not pixels: `parseFloat` gave `NaN`, a fallback hid it, and a branch with a unit spec of its own was one the app never took (#244). A size the code computes with is the page's own constant, set on the element from the same constant — or the used size (`getBoundingClientRect`).
- → A spec of rounding at `.5` cannot tell `ceil` from `round`: #244's 80.5 gave 62 both ways. Take a fraction under `.5`, where only `ceil` gives what is owed.
- → What measures "again when X changes" — an observer, a `resize` listener — has a spec where only X changes: Settings' observer and listener could go with every spec green, because every spec sized the window and showed the notice before measuring (#244).
- → A step added to a reusable workflow runs in every caller: an artifact of one name, uploaded by each run of a burn-in's matrix, is refused (409) from the second run on. Read who calls the workflow (`burn-in.yml`, `release.yml`) before adding an upload, a cache key or a concurrency group to it (#244).
- → A panel that lies over the page at a narrow width leaves focusable controls under it, and one beside the page leaves the page its leftovers: a flex item without `min-w-0` kept the list its widest line wide, and the window scrolled sideways at 640 px (#138). Try every width the window allows, down to its minimum, and measure the overflow, not the look.
- → A control that changes size or place when it is pressed is tried with the pointer where the control will be, not only where it was: "Run" is wider than "Open", grew under a double click made beside it, and the next click of that burst answered it (#32).

- → A bound in a timing spec is set against what the code does without the thing held, not against what it does with it: "a pause under a limit takes less than a second" passed with the wait deaf to the pause, because one read at the floor is a second and the unguarded pause took 980 ms. Make what is owed several times the bound, and see the spec fail with the guard taken out (#44).
- → A spec written after its code is seen failing by taking the code's line away, one at a time — also the ones that "obviously" hold: a read made "when the engine is reached, and again when it comes back" stayed green with the read made at mount only, because the spec's connection never changed (#44; #51, again). A spec whose comment names two things has a case that fails for each: "emoji where the beginning is cut, and where the end that is kept begins" held the beginning only, because in every name ten units from the end fell between two characters (#51, a third time). A guard reached from several places is taken away at each of them: the late read of Settings was held at the opening and at a change, and not after a folder was chosen, where every spec stayed green without it (#52). #131 again: the busy flag of the clipboard's reading was cleared after a read and at a turn off, and only the first had a spec. #136 again: "says the code expired, and stops asking about it" proved the second half by asking for a new code — which itself ends the old wait — so an expiry that set "failed" and went on asking stayed green; the half is now held by a code of another engine, which ends nothing of the first.
- → A list of lines taken away names the lines, and a line no road of the specs reaches is not among the "caught": the plan said "each of the service's codes unmapped" and "the account asked at every listing", and two of those lines could be deleted with every spec green — a code the simulated service is never made to answer, and a line only an engine that read its key from the vault runs. Take the line away on each road that reaches it; a line no road reaches is taken out of the code (#53: the slips of #32 and #44, both again; #65 again). #86 again: "every line that decides something" was claimed of an encoder where the directory's height byte, the planes, the mask's byte and the rule "a bitmap below 256" could each go with every spec green. Take them away with a script that removes one line, runs the specs and puts it back, and count from what it printed. #100 again: the author's script took away what was easy to name, and the tech lead's found the two lines that keep yt-dlp from going back to an older signed build — "newer than the one in use", and a date read only from what the signature covers — each removable with every spec green. A guard's mutant is the attack it stops, not its deletion: `!==` for "newer", the unsigned part read for the date. And a fix in an adapter is taken away where it is used too: `main.ts` calling the old `open` kept 393 specs green. #136 again: a code's cancel at a disconnection was taken out as "no road reaches it" because the page offers none — and the API did (`POST /code` while connected, then `DELETE`). A road is any caller of the route, not the one screen; the fix there was to close the road (a code is refused while a service is connected), not to trust that nobody takes it. #137 again: the author ran mutants on the lines it had just written, and not on the lines the round had changed by fixing them — the tech lead took the round's own lines away and four went with every spec green, among them a bound the ADR states and the save the ADR says stops a second upload. The round's mutants are taken from `git diff` of the round, every line of it, and a body says which run counted what.
- → A mutant of the line that points a run at its local host points the specs at the real one: during the fixes of round 1 of #228, a mutant took away `site`'s address of Bunkr's API, and the specs that ran under it may have posted made-up ids to the real `apidl.bunkr.ru` from the owner's machine — the one host nothing of the PR was to reach — before the run was stopped; the run kept no output to say whether a request left the machine. Every mutation run is made behind a guard that refuses `fetch`, `http` and `https` to any host but this computer's, loaded into every process of the run (`node --import`, through `NODE_OPTIONS`) and seen refusing an outside host from inside a spec before the run starts; and the lines that replace a real address by a local one are also held by a spec that asks nothing of the network (the address a `site` gives, read back). #259's round 2 again: the guard of a tech lead's run wrapped `globalThis.fetch` and `http`/`https`'s `request` and `get` — a patch of `net.Socket.prototype.connect` does not see Node's own `fetch`. #286 again: a patch of `connect` that read its options as an object let `net.connect({ host })` through, which hands the socket its arguments normalised, as an array; the probe, which tries every road (`fetch`, `http`, `https`, a socket, `net.connect`), found it before the run. A variant run in CI to see an E2E hold fail carries no guard, and is run there only when it needs none: `docs/development/testing.md`, "A hold seen failing in CI".
- → A network guard is proven against a reserved address, never a real host: `192.0.2.1` (TEST-NET-1, RFC 5737), which routes nowhere. A probe is the one spec written to be refused, and on its first run the guard is not yet known to work: in #286 the probe named `example.com`, its guard let `net.connect` through, and the socket it opened was left open — a connection to a real host from the owner's machine, by the spec meant to show that none could leave. A probe names only a reserved address, tries each road apart, and destroys what it opened.
- → A value the page computes is checked to be in the form the spec parses before anything is computed from it: a placeholder with no colour of its own computes to Tailwind's `oklab(… / 0.5)`, which a helper that took the first three numbers read as rgb — 18.92:1 for a placeholder near 3.5:1 — and the E2E spec passed in the light variant with the class it held taken away (#246). Refuse any other form (`^rgb\(\d+, \d+, \d+\)$`), and a spec that checks a variant sets that variant in main (`nativeTheme.themeSource`) rather than trusting the runner's.
- → The numbers of a run are read from that run's record, and a body that tells of several runs says which run each number belongs to: "two requests in the whole run" was the count of the last run, beside sentences from an earlier one that had made four (#53: #44 again).
- → A number in a spec's comment, and in the PR body that quotes it, is counted from the run, not from the setting: eight connections were configured, and a file of four megabytes made four (#44).
- → A wait for something new is a wait for something other than what was there. "Until the last code's check was asked twice" passed at once, on the code before — the last check the service had heard — so three specs of #136 waited for nothing and counted requests while one sent before a cancel was still arriving; under load one counted two where it had read one. A spec waits until the last thing seen is not the old one, and says what must not happen by order (nothing of the old after the new began), not by a count taken while requests may be on their way. #137 again, twice in one branch: a spec of a removed magnet counted a question already on its way, and one that slowed the service's next answer did so after the answers had come — the questions of one turn follow each other within milliseconds. Slow the service before the thing that asks, and stop a run by its own controls, not by `close()`, which cancels what the spec meant to watch. #138 again, by a save: a spec read "the first save after the call" as the take's, and on CI a turn of the watch begun before the call saved first, with no magnet — red on Ubuntu and Windows, green six times here. Read the order a promise gives: when the take answers, the last save is its own. #286 again, in the manager: "a change of the services wakes whoever waits" passed with the wake taken away, because the watch of magnets changes the list once at its first turn after the manager opens (a `setTimeout` of 0), and that change answered the spec's wait. - → A harness that runs the local hosts of a run in its own process never waits synchronously: a loop of `execFileSync` that watched for a process held the event loop, the hosts answered nothing, and the app's download sat at "Connecting…" while AllDebrid's list "did not answer" — the app was fine (#100). Use `execFile`, awaited, or put the hosts in a process of their own.
- → A program stopped is a tree stopped, and a fake of it in Node is not that tree. yt-dlp's Windows build reads the page in a second process that holds the output; `child.kill()` ended the first, `close` never came, and a page's download could be neither removed nor paused — the row came back after a restart (#170). Every spec was green: on Windows Node puts the processes it starts in a job that ends them with it, so the fake's own second process died with the first. A fake that stands for a program starting others starts them `detached` on Windows, and a spec waits for the second process to be gone; the program itself is tried, stopped mid-read, with nothing of the network (a local proxy that never answers).
- → A program the engine stops at its own stop is waited for, or its leftovers outlive it: #285's first head aborted the yt-dlp of a title in `close()` and did not wait, `main.ts` exits as soon as `close()` resolves, and the 30 MB yt-dlp unpacks were left in `%TEMP%` at every quit within a title's read — and a copy that landed during `close()`'s first `await` started a reader nobody stopped. Stop it before the first `await`, keep each run's promise, `await Promise.allSettled` of them as running downloads are awaited; and a spec's hand-answered reader ends at its signal, or `close()` waits for ever (#290). Its spec runs the real adapter over the stand-in and reads the folder once `close()` resolves.

## Electron

- → A pixel read from the screen is the pixel of whatever is on top. A harness that proved the window's own colours with `CopyFromScreen` was right nine times and then read another window's purple nine times, when something else came to the front. `PrintWindow` with `PW_RENDERFULLCONTENT` reads the window as the system composes it, covered or not (#52).
- → A window that another window covers stops drawing: a transition stays where it was, and a capture taken then shows half of two variants — rows in the light variant on a dark page, which no person ever sees. A harness that captures starts Electron with `--disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows --disable-renderer-backgrounding`, and takes no capture before what it shows has settled: a row is the colour of its token (#52). #136 again: `two-ways-to-connect.png` was taken the moment the row appeared, and its main button sat two thirds of the way between the light and the dark tokens — read in its pixels by the product designer, not by its author. A harness waits for the transitions to end (their duration, or `getAnimations()` empty) before every capture.
- → A harness closes Settings with its button, or waits for the dialog's `close` event before it presses again: the page learns that Settings closed only from that event, so a press sent in the same turn as a close is lost, and in a window that is not drawing the event does not arrive at all — Settings then opens at no press until it does (#52; the app's side is #67).
- → Two harnesses on one debugging port drive the same page: one that hung on a dialog nobody answered was still alive when the next started, attached to the new app and added every download a second time. End the old one — and bound every `fetch` to the port with a timeout — before starting another (#52).

- → A Start menu shortcut a harness makes so that a development build's notifications show carries Scia's app id, and the taskbar resolves the installed Scia through it: with an `Electron.lnk` pointing at a worktree's `electron.exe`, the installed app's button was named "Electron" (#81, #85). A harness that makes such a shortcut removes it when the run ends; a run that reads the taskbar first reads `Get-StartApps` for `app.scia.desktop`.
- → A script Electron runs ends on every road. `app.whenReady().then(async …)` with no rejection handler only logs the rejection and keeps Electron alive with its hidden window, and a `spawnSync` with no `timeout` waits for it for ever: `npm run icons` on an SVG that did not decode never ended, and left its scratch folder (#86). A handler that calls `app.exit(1)` with a message, a time limit on the spawn, and a run with a broken input and one with the limit lowered.
- → A screen that is locked has no taskbar to capture: `CopyFromScreen` returns the lock screen, flat. Look for `LogonUI` before believing a capture; the shell's icons are read without the screen (`IShellItemImageFactory`, `Icon.ExtractIcon`, `WM_GETICON`) (#81).

- → playwright-core's `_electron.launch` tells the page that the system asks for light (`colorScheme` defaults to `'light'`), while main reads the real system: every window the E2E suite and the sessions' harnesses opened on a dark Windows had a light page under the dark buttons main painted, and the owner, seeing one, filed it as the app's bug (#155). Launch with `colorScheme: null`, and set a variant in main (`nativeTheme.themeSource`), never in the page alone — the page's emulated `prefers-color-scheme` leaves the window's own colours in the other variant. Electron gives no getter for the colours of the window's own buttons: a spec records what main hands `setTitleBarOverlay`, on its way — the background colour alone stayed green with the buttons never painted (#155).

- → Chromium does not clip a `::-webkit-scrollbar` to its area's `border-radius`: once the arrow buttons were gone, the thumb of the rounded Settings dialog ran into its corners and was drawn on the veil beyond them, at the top and the bottom of its scroll (#154). A rounded area that scrolls gives its track a `margin-block` of its radius; a spec reads the corner's pixel beside the veil's.

- → A system message Electron turns into an event is read in Electron's source, at the version pinned, before the event is built on: at the end of a session Electron 44 emits `session-end` and then ends the process itself (`TerminateCurrentProcessImmediately(0)`, `native_window_views_win.cc`) unless its own quit has begun. A handler that only started asynchronous work never saw it finish: main died 45 ms after the message, exit code 0, with no `will-quit` and no `quit` line, the engine with it (#262). The unit specs and the include's integration spec were green — the fake window ended at once anyway — and CI's E2E read the log's last line. The quit is begun inside the handler and let stand: `before-quit` not prevented, the window's close not cancelled (a cancelled close cancels the quit), `will-quit` held until Scia ends itself. #262 again, one round later: the installer's include waited for Scia's windows to be gone, which stood for the process only while the window lived until the process ended — the fix that let the quit stand closes the window at once, and the include went on to electron-builder's kill while the engine still stopped. Every spec stayed green: the fake window ended its process with the window. A wait for a program to end waits on its process (a handle with `SYNCHRONIZE`), and a fake of it is given the program's own order — the window gone first, the process later. A spec of what an end wrote reads the file, not the line a pipe relays: round 2's fix wrote the state every time, and the engine's `stopped`, relayed by main from the engine's stdout, was lost in two runs of three — the engine's exit outran its pipe. Since #273 main's stop waits for the end of the engine's outputs too, and the E2E suite reads `stopped` again. Node's own child process does not show the race — it hears the exit after the output, and a probe of 240 children lost no last line — so its spec stands for Electron's order with a reader that hands each chunk on late (`engine/process-end.int.test.ts`).
- → A page's `window.close()` destroys the window at once: Electron does not emit a preventable `close` for it. A harness that wants what the X does follows `docs/development/testing.md`, "Proving the real app".
- → A harness's start that fails leaves the app it launched running on its profile, and on Windows playwright-core's `app.process()` is the shell that started Electron: `kill()` ends the shell, its exit event comes at once, and Electron — main blocked on the error box of an engine that never started — stays, holding the profile (#104). End main by the pid it reports (`process.pid` through `app.evaluate`) with its tree (`taskkill /T /F`), wait for that pid to be gone, and try it on a start that fails. Ask for that pid at once after the launch, with a bound, and fall back to the shell's tree: main stops answering `evaluate` once the error box is up, a fraction of a second after the launch returns.
- → A debugging port answers before the window has a page: a harness waits for a `page` target, not just for the port.
- → Node's `fetch` ends an answer whose body says nothing for 300 s, and a run shorter than the longest timer under a thing cannot show it: main's stream from an idle engine was cut every five minutes, and every run of the PR lasted one. A thing that lasts as long as the app is left alone for longer than every timer under it (#51).
- → A holder made for something shown once does not fit something shown many times: one variable kept the last notification, and by the comment beside it a notification nobody holds is collected with its click. Every one that can still be clicked is held (#51).
