# Skills of the plan phase

Vendored from [eai-org/agent-toolkit](https://github.com/eai-org/agent-toolkit) at commit `d0e27a01cb9d9b383f29a65546d1015c038a995c` (27 November 2026), MIT: [`LICENSE`](./LICENSE). `grill-me` is Matt Pocock's, MIT, edited by the toolkit: [`grill-me/LICENSE-grill-me`](./grill-me/LICENSE-grill-me). Why they are here and where the phase sits in the flow: [`review-flow.md`](../../docs/development/review-flow.md), "Before the code: the plan phase" (the owner, 27 November 2026, #413).

Each `SKILL.md` is the toolkit's text, unchanged, under a block `## In Scia` placed right after its title. That block, and the rules below, win over the toolkit's text wherever the two differ, and `CLAUDE.md` and its sub-files win over both. A skill is a prompt that runs with the session's permissions: it is updated only by a PR that names the new commit, reads the new text in full, and keeps each `## In Scia` block.

## In Scia: rules for every skill here

- **The ticket is the GitHub issue**, read with `gh issue view <N> --comments`, read-only. No ticket file is written: `fetch-ticket` and `attach-to-ticket` are not vendored. An image or a file the issue links, which the session cannot read, is asked of the person.
- **The planning home** of an issue is `.claude/plans/<N>-<slug>/` in the **main checkout**, the one folder every worktree shares: `"$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")/.claude/plans/<N>-<slug>/"`. It is ignored by git (`.gitignore`), so requirements, plans and decisions logs never reach the public repository by accident. It replaces every `.agents/plans/` of the toolkit. Nothing in it is committed, or pasted into an issue, a PR or a comment: it can hold a private link, which lives there and in a brief, never in the repository. What the issue or the PR must say is written there in its own words.
- **`CLAUDE.md` and its sub-files are the governing docs** the toolkit's skills read and obey: GitFlow and an issue per branch ([`git-flow.md`](../../docs/development/git-flow.md)), test first in every layer a change touches ([`testing.md`](../../docs/development/testing.md)), "Respect the hosts", and the gotchas ([`.claude/gotchas.md`](../gotchas.md) and its area files).
- **English** for every artefact. The owner may be answered in their own language in the chat; an answer of theirs that settles a decision is quoted in their own words, in the language they gave it.
- **A decision that is the owner's is never settled by a session**: what Scia does for whoever uses it, an exception to a rule of a `CLAUDE.md`, anything "Respect the hosts" decides. It is a blocking open question for the owner, drafted ready to ask. Each answer the owner gives on the issue is logged in [`docs/product/decisions.md`](../../docs/product/decisions.md) by the PR that delivers it, in the owner's words.
- **No AI attribution** in an artefact, a commit, a PR body or a comment.
- **Validation** is `SCIA_TEST_WORKERS=2 npm run gates`, one run at a time on the machine ([`git-flow.md`](../../docs/development/git-flow.md), "Work in parallel"). The E2E suite and the installer's smoke run in CI only: no run that opens Electron's windows is made on the owner's machine.
- **Who commits.** The planning skills (`refine-ticket`, `create-implementation-plan`, `harden-artifact`, `ensure-self-contained-doc`, `split-plan-tasks`) write only in the planning home and commit nothing. The session that builds works on the issue's branch and commits, pushes and opens the PR as `git-flow.md` says; the PR goes to `/team-review`.
- **A lesson** a skill would hand to `self-improve` (not vendored) becomes a gotcha or a line under "Lessons" of a role, as [`review-flow.md`](../../docs/development/review-flow.md), "Every review teaches", says.

## Left out

| Skill                                                                                      | Why                                                                                                                                               |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fetch-ticket`                                                                             | Downloads a ticket's attachments with `curl` and writes ticket files; the issue is read with `gh`, and the planning home needs no copy of it.     |
| `attach-to-ticket`                                                                         | Reads the Claude cache in the home folder and the system clipboard, and downloads URLs: outside the repository, and nothing a GitHub issue needs. |
| `self-improve`                                                                             | Edits skills and docs, at a symlink's source outside the repository too; Scia's lessons go to the gotchas and the roles' "Lessons".               |
| `self-review`, `maintainer-review`, `review-code-assistant`, `check-ticket-implementation` | The review of a PR is `/team-review`'s, which this phase does not replace.                                                                        |
| `fetch-pr-review`, `refine-pr-review`, `extract-pr-review-rules`                           | Built around reviews posted by others on a forge; the team's reviews are posted by `/team-review`, and the rules they teach go to the gotchas.    |
| `review-ticket`                                                                            | A triage before refining, through `fetch-ticket`; `refine-ticket` reads the issue and the code itself.                                            |
| `create-manual-test-instructions`                                                          | What a hand must run is the PR's runtime evidence, as `testing.md` says.                                                                          |
| `agentify-project`                                                                         | Moves `CLAUDE.md` to an `AGENTS.md`: not adopted (#413).                                                                                          |
| `memory-doctor`                                                                            | Moves and deletes the entries of the agent's memory in the home folder, outside the repository.                                                   |
| `compact-skill-creator`                                                                    | Writes new skills; none is planned, and a skill comes here only by a PR that reads it.                                                            |
| `run-nx-checks`                                                                            | Scia has no Nx.                                                                                                                                   |
| `verify-understanding`                                                                     | A teach-back over a `review-ticket` review, which is not vendored, and named by none of the skills brought in.                                    |
